# Split, freeze and evaluation-input policy

Release v1: fixed seed **20261031**, fixed source contract SHA and fixed authoring spec. SHA-256-derived tags/quantities provide deterministic variation without relying on interpreter-specific random distribution. The seed controls sample content, not opportunistic random repartitioning after evaluation.

Mapping header families stay within one partition; permutations share a family and cannot cross splits. Header signatures sorted by source names are also checked across benchmark splits. Held-out mapping includes five intended unambiguous templates plus one ambiguity per supplier (12 cases total), useful for a later 10–20-case timing protocol. Regression corruption/duplicate/size/legacy cases are not added to mapping accuracy denominators. Report their rejection/handoff behavior separately.

Query topic/language families stay within one partition. The corpus is the same known knowledge base for all splits; access to legitimate SOPs is the RAG task input, not permission to load the expected answer labels. Supplier concepts/SKUs and related topics necessarily recur in this small synthetic scenario; disjoint IDs/families do not establish full semantic independence or real-world generalization. English/Japanese paraphrases within a family remain together. Retired/conflicting/untrusted/restricted examples are explicit metadata conditions, not hidden live customer facts.

## Freeze mechanics

`data/v1/manifest.json` hashes all payload artifacts (including registries/labels), and `freeze.json` pins manifest/label hashes plus the 12 held-out CSV hashes. `data/releases/v1.lock.json` is a separately stored release pin, not regenerated by the normal generator/check command. Per-file Git attributes disable text conversion under v1; CP932, CRLF/LF, BOM, corrupt and oversize originals are preserved on Windows/Linux.

The generator writes only an empty target or confirms an identical existing tree. It refuses a differing tree and has no force/repair mode. `--check` recreates expected bytes in memory, verifies exact membership, hashes, lock/freeze consistency and semantic fixture QA. Tampering and unexpected/missing files fail. Frozen release files are not edited to improve a benchmark or silently update labels. After initial publication, any content/label correction requires a reviewed v2 spec/release/lock and a recorded reason; retain v1 evidence.

Before the first release commit, an unpublished authoring candidate was corrected because display names exposed case/family names. Neutral tags replaced those names, and the final candidate was then pinned. [Authoring record](../evidence/logs/P04-authoring-revision.log) retains previous/final candidate hashes; no previously committed release or user original was rewritten. No inference experiment had run before freeze.

## Experiment boundary

Training/development may inspect their own labels. Held-out labels belong only to the evaluation scorer/reviewer and never enter inference. The mapping input projection excludes case ID, partition, family, expected mapping, candidate profile and rationale. Corpus ingestion uses `corpus.jsonl` only. Eval IDs remain trace metadata outside model-visible text. No measured model quality exists yet; fake-provider plumbing tests are not quality evidence. Independent human label review must precede any claim of human-curated gold or customer-validated accuracy.
