## Implementation decisions and limits

Raw originals use bounded transactional BYTEA/BLOB storage rather than P02's proposed filesystem rename protocol. This keeps publication atomic and avoids temp-blob orphans; [ADR 0005](../adr/0005-transactional-document-ingestion.md) records the change. Active snapshots publish only after embedding/storage success; archived chunks remain citation-resolvable until document deletion. The delete test proves source/derived rows disappear and stale create cannot resurrect the tombstone. It does not prove secure physical disk/backup erasure.

Parser work runs in a separate process with a sanitized environment, blocked socket connects, 10-second maximum wall timeout, eight CPU seconds and 768 MiB OS-enforced memory limits. Tests run actual Windows memory-limit and timeout probes; the container verifies the POSIX worker. Unsupported DOCX constructs are rejected when the body/table parser cannot faithfully extract their text. No image OCR, table-layout fidelity, statistical extraction confidence or general malware certification is claimed.

Actor/grant checks are internal service enforcement, not deployed identity. App credentials cannot modify grants, but are trusted service SQL credentials; no PostgreSQL RLS claim is made. Write permission is rechecked after embedding; an already-authorized in-flight transaction is not cancelled by later revocation. P09 must construct trusted actors from signed BFF contexts. The current reader performs scoped candidate/citation lookup, not semantic ranking. P06 must restrict model-compatible snapshots before vector scoring.

## Failures encountered and corrected

Initial parsing/type/lint checks found long lines, Pydantic settings typing and SQLAlchemy rowcount annotations. The first ingestion run was 21 passed /8 failed /1 skipped: SQLite JSON serialized Python None as JSON null, violating the exclusive-vector-column constraint. Nullable vector variants now use SQL NULL; the full suite verifies both SQLite and PostgreSQL behavior.

The first PostgreSQL ACL test failed because `FOR SHARE` requires update privilege on the grant table. The lock was removed while retaining the final permission recheck and SELECT-only app privilege; granting app-side ACL mutation was not used as a fix. The first corpus demo exposed an actual retired-source publication bug: input order replaced current documents with old versions. Explicit manifest status ordering and retained-archive handling corrected it; final reports show current-only candidate results.

A simultaneous model download and NumPy replacement on Windows locked a DLL, leaving an incomplete older `.venv`; NumPy 2.5 stubs also exceeded the Python 3.11 mypy syntax target. The dependency now pins NumPy <2.3 and final checks use a fresh locked environment without removing the older installation. Some initial interactive diagnostics were not saved; they are summarized here rather than recreated as raw logs. Retained [initial lint](logs/P05-initial-lint.log) and [interim tests](logs/P05-ingestion-tests-interim.log) are explicitly interim, not final assertions.
