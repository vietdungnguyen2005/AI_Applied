## Delivered

- AI-only `0006_durable_runs`: run/conversation/request IDs, owner pseudonym,
  scopes, immutable TTL, bounded projected history/summaries, phase/step/revision,
  pending intent, execution lease and append-only transition metadata. Updates
  compare the expected revision and append an event in the same transaction.
  Partial actor-slot uniqueness bounds eight active runs across processes.
- Start persists before any plan/tool. Current-auth BFF resume drives at most
  three read attempts using the unchanged closed tool registry. Plans and read
  claims are checkpointed before I/O; record requires the matching live lease and
  revision. Late responses, concurrent claims, duplicate/stale resume and cancel
  races cannot overwrite a newer state.
- An expired in-flight lease becomes waiting_for_operator/OUTCOME_UNKNOWN.
  Inspection does not dispatch. Explicit uncertain-read recovery records the
  original call as unavailable and ends in abstention, without redispatching GET.
  Business handoff has terminal phase/can_resume=false; an approval payload cannot
  continue it into a business action. No background resume, tool/model retry or
  paid provider fallback was added.
- Every public command checks current Java OPERATOR/CSRF and same origin; each
  tool/result checkpoint/final response rechecks current account where applicable.
  Java independently reauthorizes GETs. Python verifies a fresh signed
  run_control context, nonce, owner, current scopes, revision, step and lease.
  Browser cannot supply actor, observations, lease, approval or private commands.
- Public snapshots contain historical status/count/time summaries. Raw question,
  cached Java bodies, known-job dispatch refs, pending intent/lease and credentials
  are not returned to the browser. Knowledge excerpts/citations are removed from
  checkpoint history; counts remain. One conversation correlation ID per run is
  implemented; multi-run conversation memory and the P12 chat UI are not.
- Fixed600-second TTL; lazy expiry/owner maintenance clears payloads. Explicit
  owner `runs-maintain` scrubs/purges bounded batches, retaining metadata until
 24hours beyond expiry. No retention scheduler/backups policy was provisioned.
  App has no UPDATE privilege on owner/identity/expiry columns, no DELETE on runs,
  and no UPDATE/DELETE on the event journal.

All defaults remain OFF/fake. P09 live-request and P10 human business routes are
unchanged. Java source/tests/business/auth contracts and both dependency lockfiles
are unchanged; no orchestration package was installed. The LangGraph comparison
is architectural, based on official documentation and current requirements;
no LangGraph prototype or performance ranking was fabricated.

## Actual process and network drills

[Final clean run](P11-real-smoke-v2.json) / [log](logs/P11-real-smoke-v2.log) executes
28 public commands against real Java, BFF, Python, owned business PG/Redis and a
separate fresh AI pgvector database. Fake planning is deterministic plumbing;
external inference count is zero. Test-only proxy holds a response **after** real
Java receives and authorizes a GET; it is not a production fault hook.

1. Normal run completes one GET; stale duplicate resume409 does not repeat it.
2. A held real read reaches HTTP504 at25.00seconds. Inspection surfaces unknown
   outcome; explicit continuation abstains without another GET.
3. During another held GET, the stored checkpoint is revision3/executing with a
   lease. The runner kills both its BFF and Python process trees, restarts them
   with the same ephemeral keys/storage, waits the existing lease boundary and
   inspects. Owner/run/conversation state survives. Explicit resume preserves an
   unavailable original call and performs no redispatch. Three total import GETs
   correspond to normal, timeout and interrupted attempts.
4. A session expires while a run is paused. Resume401 leaves its stored revision0
   unchanged. Re-login works; role downgrade403 blocks inspection. Restoring the
   current role allows explicit cancellation.
5. A business handoff cannot consume approved=true or a resume as consent.
   Current-authorized cancel closes that AI run only. Eight active runs are
   allowed; the ninth start429 is rejected by persistent quota.
6. Owner-only controlled timestamp faults in the disposable AI DB exercise TTL
   clearing of eight payloads and later purge of those eight rows/cascading
   journal records. These are simulated clock boundaries, not a24-hour wall wait.

Exact counts and sorted JSON-content hashes across eleven business tables match
before/after all commands. Auth-session/account test changes and expected AI
run/event/nonce writes are outside that business snapshot; global DB immutability
is not claimed. Current authorization can race an already received GET; cancel
or revocation cannot retroactively unread it.

[Initial drill](P11-real-smoke-v1.json) passed the restart/auth/quota/retention
checks. The [expanded intermediate run](P11-real-smoke-final.json) also passed
timeout and PG concurrency but its test proxy logged expected Windows10053 on a
deliberately aborted response. That connection-error category is now handled by
the test helper; the final v2 rerun passed cleanly and includes the bounded purge
implementation. Earlier logs are retained, not silently relabeled. All owned
services/containers were cleaned; existing user services were left alone.
