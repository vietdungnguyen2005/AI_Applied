## What changed and why

AI_Applied owns a small layered service: settings, database models, provider contracts, fake/live provider adapters, atomic budget accounting, ASGI request boundary, health/readiness and CLI. Tests isolate AI env and block non-loopback Python socket connections; live provider calls use HTTPX MockTransport. Provider keys are not used by default or sent into the Docker demo. No actual free-model quota or paid balance was consumed for P03.

Migrations create `ai.collections`, `ai.provider_controls`, `ai.provider_budget_days`, `ai.provider_usage`, the Alembic version table, and pgvector extension on the AI PostgreSQL instance. SQLite translates the AI schema for offline use and explicitly enables FK enforcement. The app role gets only AI DML/read privileges, not DDL or migration-ledger writes. Migration credentials are provided only to the migration service.

An additional per-provider control serializes unsettled live reservations across processes/day rollover. Unknown outcome or unexpected charge blocks further live calls pending manual review. Budget guards cannot prevent/refund a provider charge that contradicts its advertised price; this limit is explicit in [provider docs](../providers.md). No reset/repair tool or paid fallback is exposed.

Only health/readiness/runtime OpenAPI routes exist. Fake model/embedding behavior is callable via interfaces and `vmarket-ai fake-check`; no fake RAG answer endpoint is presented as product capability. Signed contexts and actual ToolResult projections remain P09 work. `ToolIntent` is a typed read-only interface without an executor; no Java credential/client exists.

README now separates runnable P03 quickstart from the [historical connectivity snapshot](../provider-connectivity-2026-10-31.md). Existing probe script/report remain preserved. P02 schema error enum gains three safe infrastructure error codes; its future feature schemas otherwise remain planned. Contract QA utility formatting now follows Ruff; behavior remains independently checked.

Project2 changes: none; SHA and working tree remain unchanged. No regression claim is inferred for future integration. P00's dependency-audit advisories remain OPEN; no dependency upgrade in Project2 was attempted.

## Failures encountered and corrected

Initial interactive validation found long-line/import formatting issues, four strict-mypy SQLAlchemy table-type errors and one failing test that read UTF-8 JSON using Windows cp1252. Explicit Table narrowing, formatter/import fixes and UTF-8 reads corrected them. That initial test run was 36 passed/1 failed/1 skipped. Full initial interactive output was not persisted; the actual failure/counts are disclosed here rather than reconstructed as a raw log. An interim import-order failure is retained in [lint attempt](logs/P03-lint-first-attempt.log). Later default test counts increased from 37 to 44 to 45 as the persisted-grant, malformed-provider and FK cases were added; final logs reflect the final source.

Remaining warning: Starlette TestClient's HTTPX compatibility path is deprecated in the locked versions. It is visible in raw test logs and not filtered. HTTPX remains deliberately used for the requested provider transport and current supported test compatibility; a future client migration should rerun the suite rather than hide the warning. uv hardlink fallback across drives is informational; clean install succeeds using copies.

## Security, compatibility and failure-mode evidence

- Fake mode starts without keys or an existing DB. Readiness honestly reports missing migrations instead of implying full feature availability.
- Missing live opt-in/key/budget, integrated mode, unapproved bind and a V-Market business DB name are rejected. Startup catches configuration errors without rendering values.
- Request boundary caps input at 65,536 bytes for current routes, validates correlation IDs, removes raw paths/queries from logs and returns static unexpected-error bodies. Future CSV intake is not implemented, so no five-megabyte feature claim is made.
- Safe catalog GET retries once; POST inference never retries or follows redirects. Current unknown/nonzero pricing prevents inference. All provider tests use synthetic keys/MockTransport, including 429/503-style availability handling, timeout/outer deadline, malformed usage and unexpected charge.
- Atomic reservations, serial per-provider pending grants, process-recreated ledger blocking, concurrency quota bounds and usage persistence are tested on SQLite; actual PG test exercises a reservation/settlement and verifies app permissions plus vector extension.
- Byte/shape contract validation is not signed-context/replay/ACL runtime verification. Those controls remain unimplemented and integrated mode is refused.

## Reproduction and demo

From a fresh environment, follow README: install pinned uv, sync lock, migrate default AI SQLite, run fake-check and serve. Check health 200 and ready 200; before migration ready is 503. Send invalid X-Request-ID and oversize body to observe safe 400/413. Verify future /ai/ask is 404, not a fake chatbot implementation.

For the isolated PG demo, use `docker compose up --build -d`; normal Compose project is `vmarket-ai-local`. This verification explicitly uses project **vmarket-ai-p03**. Its API remains on loopback 8090 and PG on loopback 5434. To stop the verification stack, use `docker compose -p vmarket-ai-p03 down`; do not remove another project's volumes. Data is synthetic and retained by default. The app container has only the AI app-role URL. Health checks make no LLM calls.

## Limitations, after state and commit

P03 is a local foundation, not a RAG/mapping/agent integration product. Optional live chat was not tested against a real provider; VyceAI and live embedding adapters are absent. Signature/auth replay, document ACL/ingestion, retrieval/evals, human approval UI, durable agent recovery and production networking/runbooks remain later phases. JSON safety and known local DB statement limits are not an end-to-end partition/latency SLA. PostgreSQL/Docker tags are mutable; [environment metadata](P03-environment.json) records actual observed image/version IDs. Python 3.11/3.13 are allowed but only host/Docker 3.12 was executed here.

The phase commit is the commit first containing this file: `git log -1 --format=%H -- docs/evidence/P03.md`. [Manifest](P03-manifest.json) pins staged Git blob hashes without a self-reference. Final shell output verifies branch/local-remote equality and clean AI/Project2 working trees. Local demo containers remain running for inspection; they are isolated from Project2. GitHub workflow exists; remote run state, when available, is reported separately with its actual URL/status, not fabricated in this commit.

## Interview deep-dive

1. **What can actually run today?** Health/readiness, locked install, CLI fake providers, isolated SQLite/PG migrations and Docker app. HTTP smoke and 45 offline +1 PG test provide actual evidence; RAG/mapping/tool endpoints do not exist yet.
2. **Why reserve cost for a free-only provider?** Current catalog preflight and no paid fallback reduce intended cost, but uncertain outcomes/incorrect vendor prices still need persistent accounting. Tests show single unsettled grant, unknown-state blocking and recorded unexpected charges; the guard cannot undo vendor billing.
3. **How is this independent of V-Market?** Own DB/schema/roles/ports/volume, no business API client/session/secret, and integrated startup fails closed. Actual role tests deny DDL/migration-ledger writes; Project2 remains at its original SHA with clean status.
