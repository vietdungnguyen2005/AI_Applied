## Delivered behavior

The existing human Supplier onboarding workflow now displays the expiry encoded
in Java's receipt, disables malformed/expired receipts, and rechecks expiry at
the click boundary. The original ArrayBuffer is copied before preview and reused
for confirmation. Source edits still invalidate approval.

A real browser fault test discovered that the application's default React Query
mutation retry sent **two confirm requests for one click** after a simulated 502.
Preview, confirm and recovery reads now explicitly set retry false. A confirm
error locks the source, preview and confirmation. An operator must fetch current
Import runs, inspect them and acknowledge inspection before another preview.
Failed inspection keeps the lock. Fetching or acknowledging does not resend a
request, and the new preview needs a new explicit approval. The interface warns
that absence from the latest20 does not prove nothing applied. STAGED/RUNNING is
shown as pending, and a list refresh failure after an acknowledged confirm is
handled separately from confirmation failure.

The recovery lock is browser-local. Java remains authoritative across reloads,
tabs, concurrent users, raw-byte hashes, actor/receipt validity, active profiles
and stock/product versions. No Java contract, source, test, dependency lock or
AI provider configuration changed. Other legacy mutation defaults were not
changed by this increment; broader review remains P14.
